# Repository bug sweep, 2026-09-25

Swept commit: [`9fe9cb77742d`](https://github.com/CG-AA/slime_os/commit/9fe9cb77742df437c6bb417a717f08d20deb1856) on `main`. This page records a one-off, tool-assisted static review of the whole repository and the GitHub issues it produced. It is a historical record of one sweep, not an owner of any invariant; the owning code, contracts and gates remain authoritative, and every item below is tracked by its issue.

## Method

The repository was split into 27 review partitions grouped by ownership: nine over `slime-root`, nine over `components/` and `boot-contracts/`, and nine over `scripts/`, `contracts/`, CI and Nix. One review agent read every file of its partition in full and looked for a fixed list of defect classes (memory safety, capability or rights-gate bypass, unchecked arithmetic on data crossing a trust boundary, resource accounting drift, ordering and lifetime errors, availability driven by an untrusted peer, verification gates that can pass vacuously, build non-determinism, contract/code drift). Every candidate was then re-derived by an independent verifier agent that either reconstructed the path from the untrusted input to the fault or rejected the finding. Duplicates across partitions were merged to one primary.

Nothing was booted. The container had no `just`, `nix`, QEMU or seL4 prefix, so:

- `boot-contracts`, `slime-proto`, `slime-components --no-default-features`, `slime-build-support` and the Python tooling were compiled and run on the host. Findings there are backed by throwaway reproducing tests (baseline suites green: boot-contracts 361, proto 16, components 26; `cargo miri test` and `ruff` clean).
- `slime-root`, `slime-rt`, services, drivers and applications were reviewed by code trace only. Several self-contained root modules (`shared_buffer.rs`, `io_resource.rs`, `lifecycle.rs`, the slot pool, `directory.rs`) were copied verbatim into host crates to reproduce their arithmetic and ordering defects.
- Verification-code findings were reproduced by feeding crafted transcripts to each gate's own judgement function.

Confidence per issue is stated as `confirmed-by-test`, `confirmed-by-trace`, or `plausible` (mechanism real, one link unproven; the issue title carries `[needs QEMU confirmation]` or `[needs hardware confirmation]`). Findings the verifier rejected are listed at the end and were not filed.
